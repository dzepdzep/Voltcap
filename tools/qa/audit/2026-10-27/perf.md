# VoltCap perf & reliability audit (read-only, src_copy)

I ranked these by how much they cost during normal home navigation, using the defaults: CLASSIC layout, ELECTRIC focus effect, theme colours set to THEME.
CONFIRMED means I followed the mechanism in the code. PLAUSIBLE means the mechanism holds up but its size needs a Perfetto trace.
The code already has good mitigations in many places: the carousel and dock read their glide in the draw phase, the visibleGames memo, artRequest sizing and keys, SceneClock naps, and HomeIdle gating. The items below are what is still left.

## Proposed `vcTrace` sections (Perfetto: `atrace -a com.shelf.launcher view gfx`)
1. `VC:ScreenContent` wraps the body of `LauncherScreenContent` (ui/LauncherScreen.kt:349). It shows the per-step root cost (P2) and the glide re-runs (P3).
2. `VC:Theme` wraps the `ShelfLauncherTheme` body (ui/theme/Theme.kt:44-212). Counting slices per frame during a colour glide gives P3.
3. `VC:GameDock` (whole dock) and `VC:GameCard` per card, around the `GameCard(` call in ui/GameDock.kt:589. These are the Classic row's per-step and 20 Hz pulse costs (P1).
4. `VC:visibleGames` wraps `computeVisibleGames()` in the memo (LauncherUiState.kt:421). Several slices per category press means CAS retries (P7).
5. `VC:R1Open` wraps the first composition of `QuickSettingsCard` (ui/QuickSettings.kt:186). Put `VC:R1Probe` around lines 203-207 and 305-307 (P6).
6. `VC:GameWindow` goes around the game window or details composable when it opens (ui/GameWindow.kt top-level composable), with `VC:DetailsOpen` in `openDetails` (ui/LauncherScreen.kt:~420).
7. `VC:TplDecode` goes in a shared helper replacing the `imageResource`/`painterResource` calls in RealMedia and CoverCases (P5), plus `PackSpines.load` (P12).
8. `VC:Trim` wraps `TrimUniformMargins.transform` (ui/TrimMargins.kt:80). It runs on Coil threads; compare it with the RenderThread "Upload" slices (P4).
9. `VC:SceneDraw` wraps the `onDrawBehind` body of ShaderScene (ui/ThemeScene.kt:286-299). `VC:SceneTick` wraps the `withFrameNanos` step in SceneClock (:245).
10. `VC:SecondScreen` wraps `currentContent()` in the Presentation ComposeView (ui/SecondScreen.kt:244). It separates second-screen cost from the main-screen cost (P13).

Tip: add `androidx.compose.runtime:runtime-tracing`, which matches the BOM, to a debug or benchmark build. Perfetto then names every recomposed function automatically, which makes P1, P2 and P3 obvious without hand-placed sections.

Notes: the stability configuration that build.gradle.kts references (`app/compose_stability.conf`) is not in the upload, so I could not check stability for parameter types. I did not read ui/ThemeShaders.kt.
