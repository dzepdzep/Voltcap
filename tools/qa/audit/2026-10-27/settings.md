# VoltCap settings wiring audit

Source: `/mnt/user-data/uploads/ShelfLauncher/src_copy` (read-only; `ui/ThemeShaders.kt` not read).
Tool: `settings_inventory.py` (stdlib only), which writes `settings_inventory.csv` (1169 rows) and `stale.csv`.
Re-run it with: `python3 qa/tools/settings_inventory.py <src> -o settings_inventory.csv --stale stale.csv`
Helper used once for this audit: `unused_params.py <src> <csv>` (finds setting values passed into parameters the function never uses).

The static pass found **no setting that the UI writes but no code reads**. The candidates it first flagged (Edit-Home art and widget positions, `second_games_look`, `pq_sounds`, `show_rarity`, `dock_position`, …) all turned out to have readers once I traced them. They are read through helper objects (`ArtPlace`, `HomeWidgets`, `PqSynth`), through extension properties (`dockHere`, `statusOn`), or inside a popup that both picks and uses the value. The script now classifies these correctly. The real defects are the subtler kinds listed below.

### What was checked and came back clean
- **Load/save keys:** AppearanceSettings load key = save key for all 158 fields, and every field is both loaded and saved.
- **Duplicate keys:** none in Features or appearance.
- **Type mismatches:** no getX/putX type mismatch on any (file, key) pair in the codebase.
- **Mixed-up controls:** no Settings control shows one pref and writes another (checked/onChange pairs).
- **R1 tiles vs Settings:** these match. Badges, Outline, Endless, Round shortcuts, Game size, Corners, Categories, Row position, Carousel, Background, Picture fit (`HeroFitPlan`), Popup style and Gaps toggle the same prefs as their Settings entries. Most earlier mismatches were already fixed in update 329, per the in-code notes.
- **Values copied at startup:** checked Discord presence, weekly recap, AnimatedArt and the ConsoleLogos/TitleStrip mirrors. Each is either applied live on change or documented.
- **Backup:** every core setting is in a GLOBAL or DEVICE file. `voltcap_features` is unlisted, so it defaults to GLOBAL. Import calls `Features.reload` or restarts the app.

## Script notes (`settings_inventory.py`)
- Extracts every `val x = Bool/Enum/String/Int/SetPref("key", default…)` in Features.kt, every AppearanceSettings field (with the load key, save key and default), and every `prefs.getX("key", default)` in files that open SharedPreferences. It works out which file a call reads through helpers and locals such as `prefs(c)`, `state(c)` and `val p = …`.
- References: comments are stripped and ThemeShaders.kt is skipped. Each reference is classified as `ui` (settings files and `*Settings`/`*Options` composables, but not behaviour objects inside them), `r1` (QuickSettings / R1*), `infra` (presets, preview, backup, index) or `code`. Writes are `.value =`, `.toggle()`, `.setByName()` and `copy(field = …)`. A bare pref passed inside UI counts as a control.
- Flags: `unread_but_ui`, `no_ui`, `unused`, `stale_copy`, `not_backed_up`, `duplicate_key`, `load_save_key_mismatch`, `not_loaded`, `not_saved`, `readers_uncalled`.
- Limits: matching is by name, so a field with a common name can be over-counted, and reads that pass through local variables or unused parameters aren't followed (see `unused_params.py`). "Searchable" compares labels near the control with index labels.
